This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Native (no framework, no bundler, no CSS framework) TypeScript hospital queueing app ("Antrian Rumah Sakit") for a Pemrograman Web practicum (Modul 3). Five static HTML pages, each with its own TypeScript entry point, sharing a small services/types/utils layer. Auth and role lookup hit the public `dummyjson.com` API; all app state (session, queue types, tickets) lives in `localStorage`.

**Styling is intentionally out of scope for this codebase.** `css/style.css` is a deliberately empty placeholder — do not add CSS rules or inline styles unless explicitly asked; it's being styled manually elsewhere.

## Commands

```bash
npm install

npm run build       # tsc (src/**/*.ts -> dist/) then copies root *.html + css/ into dist/
npm run dev         # build once, then run tsc --watch + html/css watcher + live-server on dist/ concurrently
npm run watch        # tsc --watch only (no asset copying)
npm run typecheck    # tsc --noEmit
npm run copy:assets  # one-shot copy of root *.html + css/ into dist/, no compile
```

There is no test suite and no lint script configured.

Two ways to run the app:
1. `npm run build`, then open the **project root** with VS Code Live Server (root HTML references `dist/*.js` directly — matches how the practicum expects the repo to be opened).
2. `npm run dev` — self-contained: serves `dist/` via `live-server` with auto-reload.

## Architecture

### Module system — read this before touching any `src/*.ts`

- `tsconfig.json` uses `module`/`moduleResolution: NodeNext` with `rootDir: src`, `outDir: dist`. Relative imports **must** include the `.js` extension (e.g. `from "../types/index.js"`) even though the source file is `.ts` — this is required by NodeNext resolution, not a typo.
- Everything is a real ES module (`import`/`export`), loaded in the browser via `<script type="module">` — no bundler, no global namespace tricks.
- Each HTML page loads exactly one entry script: `login.ts`, `admin.ts` (→ `index.html`, note the name mismatch), `operator.ts`, `layar.ts`, `ambil-antrian.ts`. These live directly under `src/`; everything they import lives in `src/services/`, `src/types/`, `src/utils/`.

### HTML/dist duality (important, easy to break)

Root `*.html` files reference scripts as `src="dist/<name>.js"` so the repo root can be opened directly by Live Server without a build step for the HTML itself. `scripts/copy-assets.mjs` copies those same root HTML files into `dist/`, but **rewrites `src="dist/foo.js"` to `src="foo.js"`** in the copies (regex in `copyHtml()`), because inside `dist/` the HTML and its compiled JS sit in the same directory. This is what lets `dist/` also be served standalone (`npm run dev` via `live-server dist`). If you add a new page/script, keep this `dist/`-prefix convention in the root HTML — the copy step depends on it.

`scripts/copy-assets.mjs` also copies `css/` → `dist/css/`, and supports `--watch` (used by `npm run dev`) which re-copies on any top-level `*.html` change or any change under `css/`.

`dist/` is gitignored — it's fully regenerated by `npm run build`/`npm run dev`, never hand-edit files in it.

### Service layer (`src/services/`)

- **`storage.service.ts`** — the only module touching `localStorage` directly. Typed read/write for three keys: `antrian:session`, `antrian:queue-types`, `antrian:tickets`. All other modules go through this rather than calling `localStorage` themselves.
- **`api.service.ts`** — talks to `https://dummyjson.com`. `POST /auth/login` returns `accessToken` but **no `role` field** (verified against the live API); role comes from a follow-up `GET /users/{id}`. Preserve this two-step flow if you touch auth.
- **`auth.service.ts`** — combines the two API calls into `login()`, plus `enforceLogin()` / `enforceAdmin()` guards that redirect to `login.html` and return `null` (callers must check for `null` and bail — these guards never throw). `moderator` is treated as equivalent to `admin` everywhere via `isAdminRole()`.
- **`queue.service.ts`** — all domain logic for queue types and tickets (CRUD, validation, ticket numbering, priority ordering, call/skip/complete). This is the core module; page scripts are thin DOM glue around it. Key invariants:
  - Queue type `code` is always a single uppercase letter; `createQueueType` normalizes and rejects case-insensitive duplicate codes/names.
  - Ticket numbers are per-queue-code sequential (`max existing + 1`), reset to 1 by `resetAllQueues()` (clears all tickets).
  - Waiting-ticket order is priority desc (`VIP > Disabilitas > Lansia > Normal`) then FIFO by `createdAt` — see `sortWaitingOrder`.
  - At most one ticket per queue can be `Dipanggil` at a time; `callTicket()` auto-completes any other called ticket in the same queue first.
  - `ensureSeedData()` seeds 3 default queue types (Umum/Gigi/Farmasi) only when storage is empty — called at the top of every page entry script.

### Page scripts (`src/*.ts`)

Each is self-contained: call `ensureSeedData()`, run an auth guard if the page needs one, then fully re-render its DOM from `queue.service.ts` state on every mutation (no diffing/virtual DOM — full `innerHTML` rebuild via small `render()` functions). Event handling uses delegation with `data-action`/`data-code`/`data-ticket-id` attributes rather than per-element listeners. `layar.ts` and `ambil-antrian.ts` additionally `setInterval` their `render()` every 2.5s to pick up changes made from other tabs/pages (`localStorage` doesn't fire same-tab events, so polling is the mechanism, not the `storage` event).

### Auth/role flow

- `index.html` (admin dashboard) and `operator.html` are guarded (`enforceAdmin()` / `enforceLogin()`); `layar.html` and `ambil-antrian.html` are public.
- Session shape: `{ id, username, firstName, role, token }`, persisted via `storage.service.ts`.
- Test accounts: <https://dummyjson.com/users>, or filtered by role via `/users/filter?key=role&value=admin|user`.
